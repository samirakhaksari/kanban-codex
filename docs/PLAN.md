# برنامه اجرایی پروژه کانبان

## مرجع، وضعیت فعلی و تصمیم‌های قطعی

این فایل، برنامه مرجع پروژه است. فایل PLAN.md در ریشه پروژه حذف شده و برنامه‌ریزی فقط در docs/PLAN.md نگهداری می‌شود.

ساختار فعلی پروژه:
- فرانت‌اند موجود در frontend یک برنامه Next.js با App Router و TypeScript است. برد نمونه، صفحه اعضای تیم، مدیریت ستون‌ها و کارت‌ها، فیلترها، داده‌های نمونه و ذخیره‌سازی سمت مرورگر در آن پیاده‌سازی شده است.
- آزمون‌های موجود فرانت‌اند با Vitest و Playwright اجرا می‌شوند؛ فرمان‌های آن‌ها در frontend/package.json تعریف شده‌اند.
- بک‌اند FastAPI در backend/app قرار دارد؛ نقطه سلامت، ورود آزمایشی با نشست cookie امضاشده، middleware محافظ API، راه‌اندازی SQLite در مسیر KANBAN_DATA_DIR و API احراز هویت‌شده برد را دارد. نمونه برد هنگام نخستین خواندن API ساخته می‌شود تا مهاجرت localStorage در مرحله هفتم بتواند پیش از آن انجام شود.
- پوشه scripts اسکریپت‌های شروع و توقف Docker برای Windows و macOS/Linux را دارد.
- Dockerfile چندمرحله‌ای خروجی استاتیک Next.js را می‌سازد و همراه FastAPI در یک تصویر نهایی بسته‌بندی می‌کند؛ دستورهای اجرای محلی در docs/LOCAL-SETUP.md هستند. frontend/AGENTS.md بخش تولیدشده دستورالعمل Next.js را دارد و هنگام افزودن توضیح پروژه باید حفظ شود.

تصمیم‌های ثبت‌شده:
- برنامه محلی در یک کانتینر Docker اجرا می‌شود. FastAPI فایل‌های استاتیک خروجی Next.js را از مسیر / و API را زیر مسیر /api ارائه می‌کند.
- برای بک‌اند از FastAPI و uv، برای داده از SQLite محلی و برای درخواست‌های مدل از OpenRouter استفاده می‌شود.
- نام مدل openai/gpt-oss-120b و نام متغیر محیطی کلید OPENROUTER_API_KEY است. کلید فقط در بک‌اند استفاده می‌شود و نباید در کد فرانت‌اند یا مخزن قرار گیرد.
- ورود MVP فقط با نام کاربری user و رمز عبور password انجام می‌شود؛ ثبت‌نام و مدیریت واقعی کاربران در دامنه MVP نیست. ساختار داده باید از چند کاربر پشتیبانی کند و هر کاربر در MVP یک برد داشته باشد.
- دستیار هوش مصنوعی می‌تواند کارت بسازد، ویرایش کند یا جابه‌جا کند. تغییر معتبرِ برگشتی از مدل بدون درخواست تأیید جداگانه اعمال می‌شود.
- کاربر باید پیش از شروع پیاده‌سازی، این برنامه را مرور و تأیید کند. طرح پایگاه داده نیز پیش از پیاده‌سازی ذخیره‌سازی باید جداگانه تأیید شود.

## تصمیم‌های داده ثبت‌شده

با درخواست کاربر برای انتخاب مسیر مناسب، این تصمیم‌ها برای طرح مرحله پنجم ثبت شدند:
1. تیم‌ها، اعضا و انتساب چند عضو به کارت در SQLite حفظ می‌شوند تا قابلیت‌های موجود رابط کاربری حذف نشوند.
2. نخستین مرورگری که با وضعیت معتبر وارد حساب آزمایشی می‌شود، داده‌های localStorage خود را یک‌بار وارد می‌کند. اگر داده‌ای موجود نباشد، نمونه آغازین ساخته می‌شود. چون حساب آزمایشی بین مرورگرها مشترک است، داده‌های localStorage مرورگرهای دیگر خودکار ادغام نمی‌شوند.

تا زمان تأیید نهایی کاربر از طرح، ساخت جدول‌ها و API پایدارسازی شروع نمی‌شود.
